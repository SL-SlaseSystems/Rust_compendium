# 19. Runtime, pamięć i kompilator

## Dla kogo i po co

Dla czytelników, którzy chcą rozumieć decyzje borrow checkera, ewolucję analizy pożyczek i relację między modelem języka a implementacją kompilatora.

## Wymagania wstępne

Ownership, lifetimes, traits i doświadczenie z komunikatami kompilatora.

## Kolejność materiałów

1. [Borrow checker, Polonius i model pamięci](01_borrow_checker_polonius_i_model_pamieci.md)

## Po tym dziale

Umiesz odróżnić stabilne gwarancje języka od szczegółów bieżącej implementacji i lepiej diagnozować złożone konflikty pożyczek.

## Co dalej

Kontynuuj przez optymalizację, model pamięci `unsafe` albo implementację własnych narzędzi wokół kompilatora.
